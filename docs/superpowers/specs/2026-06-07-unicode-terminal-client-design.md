# Unicode Terminal Client Design

## Goal

Phase 8 upgrades Terminal Mahjong from a command-driven text loop into a modern terminal client while keeping the project terminal-first. Normal play should feel like selecting and discarding tiles in a lightweight client: Unicode Mahjong tiles, highlighted selection, keyboard navigation, mouse clicks, a start screen, and a table-like layout.

## Assumptions

- The existing rules engine remains the source of truth for tile state, turns, claims, scoring, events, and replay-ready logs.
- The new UI is still a terminal application, not a desktop GUI or browser app.
- Bubble Tea is the preferred TUI framework because it provides an application event loop, keyboard events, mouse events, and full-screen rendering.
- Unicode Mahjong glyphs are the default visual skin, with a text fallback for terminals or fonts that cannot display them clearly.
- Phase 8 focuses on solo play polish. Replay viewing remains a later phase because Phase 7 only made logs replay-ready.

## User Experience

The game starts in a full-screen terminal menu:

- `Solo Game`
- `How to Play`
- `Quit`

The menu supports arrow-key movement, `Enter` confirmation, and mouse selection when the terminal supports it. `Solo Game` enters the table screen. `How to Play` shows compact controls and tile notation. `Quit` exits without starting a round.

The table screen is arranged like a Mahjong table:

- Top: opposite AI player.
- Left and right: side AI players.
- Center: last action, claim prompt, wall count, current turn, shanten/wait hints, recent event summary.
- Bottom: human player melds, discards, hand tiles, selected tile marker, and shortcut bar.

Normal play does not require typing commands. The main controls are:

- `Left` / `Right`: move selected hand tile.
- `Enter` / `Space`: discard selected tile when discarding is legal.
- Mouse click on a hand tile: select that tile.
- Second click on the selected hand tile: discard it when discarding is legal.
- `H`: self-win or claim win when available.
- `P`: claim pong when available.
- `C`: claim chow when available.
- `K`: declare concealed kong when available.
- `Esc`: decline a prompt or cancel the current transient selection.
- `Q`: quit the current game.

Number-based discard input may remain as a fallback, but it is not the primary interaction.

## Visual Skin

Tiles are rendered with Unicode Mahjong glyphs:

- Characters: `🀇` to `🀏`
- Bamboos: `🀐` to `🀘`
- Dots: `🀙` to `🀡`
- Winds and dragons: `🀀 🀁 🀂 🀃 🀄 🀅 🀆`

Each tile still keeps its internal notation (`1m`, `9p`, `E`, `B`) for rules and tests. Rendering maps internal tiles to glyphs through a small display layer.

The selected hand tile must be visually obvious using at least two signals:

- Accent color or inverse style.
- Raised marker, underline, border, or cursor marker.

The table should use restrained terminal styling: box borders, clear spacing, and color for state rather than decorative noise. It should look like a client built for repeated play, not a marketing screen.

## Architecture

Phase 8 adds a TUI adapter around the existing game package instead of rewriting game rules.

Proposed package split:

- `internal/game`: existing rules, state transitions, scoring, events, replay log. Keep this independent of Bubble Tea.
- `internal/game/tile_display.go`: maps `Tile` values to Unicode glyphs and fallback labels.
- `internal/tui`: Bubble Tea models, messages, input handling, layout rendering, and start menu.
- `cmd/mahjong`: starts the TUI app by default.

The TUI layer should drive game actions through small methods on `Game` where needed. If the current `Play(in, out)` loop is too coupled to blocking input, Phase 8 may add focused step/action methods such as applying a discard or handling a claim. Those methods should stay small and be covered by tests.

## State Model

The TUI model needs these UI-only fields:

- Current screen: start menu, help, table, game over.
- Menu selected index.
- Selected hand tile index.
- Pending prompt: none, win, pong, chow, kong, quit confirmation.
- Glyph mode: Unicode or text fallback.
- Mouse-enabled layout hit boxes for the human hand.

Game state remains inside `*game.Game`.

## Mouse Interaction

Mouse support is part of Phase 8. The implementation should enable Bubble Tea mouse events and map click coordinates to hand tile hit boxes generated by the current render layout.

Acceptance behavior:

- Clicking a hand tile selects it.
- Clicking the same selected tile again discards it if it is the human discard turn.
- Clicking a different hand tile changes selection without discarding.
- Clicking menu items selects or activates them according to the screen.
- If the terminal does not provide mouse events, keyboard controls still fully work.

## Testing Strategy

Tests should avoid depending on a real terminal.

Required coverage:

- Tile glyph mapping for all suits, winds, and dragons.
- Text fallback labels for all tile categories.
- Selection movement clamps or wraps predictably across the hand.
- Enter/Space discards the selected tile only during a valid discard turn.
- Mouse click hit testing selects the expected tile index.
- Second click on the selected tile produces a discard command.
- Start menu navigation with arrow keys and Enter.
- Table rendering includes Unicode glyphs in Unicode mode and text labels in fallback mode.
- Existing `go test ./...` remains green.

Manual smoke acceptance:

- Launch `go run ./cmd/mahjong`.
- Start screen appears before the game.
- `Solo Game` starts a round.
- Human hand uses Mahjong glyphs by default.
- Arrow keys move the selected tile.
- Enter discards the selected tile.
- Mouse click selects a tile in a terminal that supports mouse events.
- Second click discards the selected tile.
- `Q` quits and shows a game-over summary with replay-ready status.

## Out of Scope

- Desktop GUI.
- Browser UI.
- Network play.
- Replay viewer.
- Full regional scoring or fan tables.
- Rich animation beyond simple terminal redraws and highlight states.
- Rewriting the rules engine.

## Acceptance Criteria

Phase 8 is accepted when:

- The game starts with a TUI start menu.
- The table screen uses a table-like layout instead of the old section-only printout.
- Human hand tiles render as Unicode Mahjong glyphs by default.
- A text fallback rendering mode exists and is testable.
- Keyboard tile selection and discard work without typing numbered commands.
- Mouse click selection works where mouse events are available.
- Existing game logic tests still pass.
- New TUI/rendering tests cover glyph mapping, selection, mouse hit testing, and start menu navigation.
- The final app remains runnable with `go run ./cmd/mahjong`.
